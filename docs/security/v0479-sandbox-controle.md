## Detalhe dos achados
**A1.** Evidência: S1 mostra que o runtime do sandbox, para cada caminho negado que não existe dentro da área gravável, cria no disco um arquivo regular vazio, modo 0444, e o monta só leitura; o próprio `.gitignore:6-8` do Forge descreve isso ("arquivos e pastas vazios, somente leitura, criados na raiz"). Os arquivos fecham a sessão no disco. No modelo (`templates/projeto/.claude/settings.json:38-41`): `pesado.json` é apagado pelo hook a cada soltura (`hooks/pesado.py:386-387`) e, no comando Bash seguinte, volta como vazio; a próxima tarefa pesada lê com `ler_json` (`:384`, `hooks/_comum.py:2499`), que levanta, e `executar` sem `critico` (`hooks/pesado.py:450`, `_comum.py:2778-2780`) libera: a trava pesada (R-TETO) deixa de valer depois da primeira soltura, em silêncio, com uma linha no `erros.log`. `agentes.json` não existe num projeto novo até o primeiro disparo; o primeiro Bash da sessão o cria vazio, `ler_estado` o declara ilegível (S2, `hooks/agentes.py:41-44`: "nenhum evento regrava o arquivo ilegível") e todo `Agent` é recusado com R-TETO até o dono apagar o arquivo, que o Bash seguinte recria. Caminho: não é ataque, é negação de serviço que o próprio controle causa em todo projeto que ligar o sandbox do modelo; o efeito no pesado é o inverso do pedido (o controle abre). Severidade: alta (quebra R-TETO nos dois sentidos, em todo projeto).
