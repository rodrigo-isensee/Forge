## Detalhe dos achados
**A3.** Evidência: `hooks/conformidade.py:2785-2786`; `docs/hooks.md:76` ("sem rodar a configuração da cópia"). Caminho de ataque: o agente, no sandbox, faz `git init` num repositório seu, grava `extensions.partialClone`, `remote.origin.promisor`, `remote.origin.url` local e `remote.origin.uploadpack` com o comando, aponta `refs/remotes/origin/develop` (ou `HEAD`) para um commit que não existe ali e pede o Write de `docs/reviews/x.md` nesse repositório. O hook, fora do sandbox, roda `cat-file -e <ref>:<lista>`, o git não acha o objeto e busca do promisor executando o `uploadpack`. Controle: o mesmo repositório com Write em `src/v1.md` não cria a marca (é a `lista_fechada`). Severidade alta (execução fora do sandbox, como o A1). Correção mínima, esforço P: `git(topo, "-c", "protocol.allow=never", "cat-file", "-e", ...)` (sondado: com ela, `fatal: transport 'file' not allowed` e sem marca; vale para todo transporte, inclusive `ssh` e `ext`, que levariam `core.sshCommand`); a versão do git da estação (2.43) não tem `GIT_NO_LAZY_FETCH` nem `--no-lazy-fetch`. Teste: o `test_uploadpack_da_copia_nao_roda` ganha a variante do clone parcial (as quatro configurações acima e o ref para um sha ausente), com a marca ausente; o mesmo vale para o fixture. Dono: o autor do C1b-2.
