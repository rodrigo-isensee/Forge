M9 da catraca no alcance S1 + S2 (pedido EST-030-L3-REV, E1.1). Diff lido: `d150ec87b004f6f5561a65aa130bb16cf454473c...c71f8a57d299c0db58bfe173106ad2e9f408a4e1` (16 arquivos, 7 commits). Revisor: instância que não implementou o lote.

## Achados
- A1 (bloqueante) tests/catraca.py:537 · segurança com gatilho: S1 trata a linha do shebang como comentário; trocar `#!/usr/bin/env python3` por `#!/bin/true python` no bin/forge-check (100755, chamado pelo PATH em bin/forge-fechar:535) passa sem rótulo e o forge-check sai 0 sempre
- A2 (recomendado) tests/catraca.py:529 · o arquivo conta como Python só pelo shebang do head; exigir que base e head sejam Python (extensão ou shebang nos dois lados) fecha a troca de linguagem por cima de um script da base que por acaso compila como Python

## Parecer
**Reprovado**, por um achado (A1). O resto cumpre a decisão M9 no alcance S1 + S2 do dono.

**A1, prova.** Sonda em `$TMPDIR/tech-lead-est-030-l3/sonda_shebang2.py`, sobre o harness `Repo` de `tests/test_catraca.py`: `bin/forge-check` com modo 100755 na base e no head, só com a primeira linha trocada. `regra_protegidos` devolve `[]` e `violacoes_das_regras` também devolve `[]`, tanto para `#!/bin/true python` quanto para `#!/usr/bin/env -S python3 -c pass`. Um arquivo executável com `#!/bin/true python` sai com rc=0 sem rodar o corpo. O `bin/forge-check` roda pelo shebang: `bin/forge-fechar:535` chama `"$check" pr ...`, e os agentes chamam `forge-check pr` pelo PATH. Então o passo 1 do fechamento passaria calado. Os hooks (`hooks.json`) e o `scripts/conferir-release.py` (`ci.yml:147`) são chamados com `python3 <arquivo>`, e neles o shebang não tem efeito. O modelo de ameaças define a S1 como "só comentário, espaço ou quebra de linha", mas o shebang é um comentário para o Python e uma instrução para o `exec` do sistema. A ADR 0008 (`docs/adr/0008-governanca-de-contribuicoes.md:56`) repete a mesma lacuna. **Sugestão:** na S1 e na S2, exigir que a primeira linha seja igual byte a byte quando base ou head começam com `#!`. Isso também cobre o cookie de codificação, que já está na AST. Acrescentar um teste nomeado com os dois shebangs acima pedindo o rótulo e ajustar a frase da ADR. **Classe:** segurança com gatilho. Esforço P, e só toca `tests/catraca.py`, `tests/test_catraca.py` e a ADR. Este achado também vai como cartão ao `security-engineer`, que dá o parecer E2.1.

**A2.** `re.match(rb"#!.*python", depois)` só olha o head. Caso contrivido: na base, um shell só com comentários e `true` (o que também compila como Python); no head, só o shebang trocado para Python. A AST é igual e o arquivo muda de linguagem. Hoje isso deixa o hook mais estrito, não mais largo, por isso o achado é recomendado. Com a sugestão de A1, ele deixa de existir.
